# CSV 导入复查

- 用户要求：两个入口均检查；已有用户/成员跳过，后续行继续，成功导入的账号可正常登录使用；提交并推送 feature。
- 基础复现：当前账号入口遇到已有邮箱、文件内重复仍可继续；12 个 pending 账号导入为 user 并逐一登录通过。
- 已确认遗漏：账号 CSV 在解析时将邮箱加入去重集合；首行请求失败后，后续同邮箱有效行不再尝试，且误计为已有用户。注入单次 503 复现只有 1 次请求、目标账号未创建。
- 用户组入口：后端已有幂等添加，但前端仍提交已有成员，且缺少跳过计数；成员 CSV 仅关联已有账号，不创建账号。
- 同一问题也在用户组入口复现：成员 ID 在发出添加请求前去重，首行添加失败后，后续同用户行被丢弃。注入单次 503 后回归报 `A failed membership must not suppress a later row with the same user.`。

## 实施与验证计划

1. 账号逐行隔离创建结果，仅在确认存在/创建成功后记录去重；失败行报告并继续。
2. 用户组解析现有成员关系，跳过已加入成员及文件内重复，显示跳过计数；其余错误继续后续行。
3. 浏览器回归两个真实导入入口，包含跨旧批次边界、已有账号、重复行、首行失败后重试、找不到的组成员、重复导入；新账号逐一登录及校验有效会话。
4. 运行定向测试与生产构建，刷新本地运行页面，提交并普通推送到 feature。

- 浏览器回归脚本：`test/browser/user-csv-import.js`，仅允许隔离 QA 服务 `http://127.0.0.1:18080`，不会操作原有业务数据库。
- 回归测试已在实施前验证失败：`A failed first row must not suppress a later row with the same email.`。
- 已修改：两个入口均在写入结果确认后去重，失败不标记完成；组成员预查 `group_ids` 跳过已有成员并累计重复行；单行失败继续。
- 验证完成：29 项 Vitest、4 项后端账号事务测试和最终生产构建（2m 6s）通过。
